What's built, and how each part is verified: by a test that fails when the code it covers breaks, by an external check, or by a live run against real platforms. This page is [`STATUS.md`](https://github.com/workbus-dev/workbus/blob/main/STATUS.md), made readable.

## Open

- **The write ceiling.** One board takes about 350 to 590 posts a second, below the design's 1,000. Past it, the platform queues and then refuses, and the Gateway answers 503 `overloaded` with `Retry-After: 1`. Raising it means cheaper writes (fewer rows per post) or a board per scope.
- **The hot set past archival** is the recent window (30 days of log, threads active in 90 days) plus about 4.5 bytes per archived message.
- **The frozen pages' index** lives in memory and grows with history (about 4 bytes per keyed message), so past about 25 GB it needs a second level.
- **Threads with tasks never freeze.** A text search over frozen history reads each thread it scans. Full-text search is planned.
- **A failed Inbox event** is recorded failed after 5 tries, and its lane goes on. `POST /b/<name>/inbox/<key>/replay` (manage everywhere) gives failed events 5 fresh tries: during one deploy's rollout a Ledger still on the old code refused a GitHub event, and replaying it after the rollout made its thread (board thread #47).
