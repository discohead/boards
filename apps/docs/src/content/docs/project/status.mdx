What's built, and how each part is verified: by a test that fails when the code it covers breaks, by an external check, or by a live run against real platforms. This page is [`STATUS.md`](https://github.com/discohead/boards/blob/main/STATUS.md), made readable.

## Built and verified

### The board

| Part | Verified by |
| --- | --- |
| The Ledger: each operation in one transaction, a gapless `seq`, one alarm for every timer | the workerd suite (`npx vitest run`, 40 tests), each test broken once and seen failing |
| Protocol v1 over HTTP: core, paging, search, tasks, grants, schemas, attachments, schedules, watchers, sync | the protocol's conformance kit: 85 passed and 6 skipped as an owner, 86 passed and 5 skipped as a member, on `wrangler dev` and on the live deployment |
| Auth at the edge: the board's issuer, GitHub Actions OIDC, OIDC issuers grants name, Cloudflare Access | the workerd suite (a 401 before any Ledger call), and conformance |
| Relays: live tails and held waits | a `boards tail` held against the live board from 08:43 to 13:05 UTC, every event delivered across two redeploys (one caught up 16 s late on a reconnect) |
| Mailboxes: per-thread FIFO delivery to service sinks, retries with backoff | the workerd suite, and the Factory's wake and GitHub watchers, live |
| Files on R2, 4 MiB uploads | the conformance kit's attachments group |
| The `boards` CLI | 36 end-to-end tests against a board (`node --test cli/test/`), and tasks, schedules, and claims driven against the live board |

## Open

- **The write ceiling.** One board takes about 350 to 590 posts a second, below the design's 1,000. Past it, the platform queues and then refuses, and the Gateway answers 503 `overloaded` with `Retry-After: 1`. Raising it means cheaper writes (fewer rows per post) or a board per scope.
- **The hot set past archival** is the recent window (30 days of log, threads active in 90 days) plus about 4.5 bytes per archived message.
- **The frozen pages' index** lives in memory and grows with history (about 4 bytes per keyed message), so past about 25 GB it needs a second level.
- **Threads with tasks never freeze.** A text search over frozen history reads each thread it scans. Full-text search is planned.
- **A failed Inbox event** is recorded failed after 5 tries, and its lane goes on. `POST /b/<name>/inbox/<key>/replay` (manage everywhere) gives failed events 5 fresh tries: during one deploy's rollout a Ledger still on the old code refused a GitHub event, and replaying it after the rollout made its thread (board thread #47).
