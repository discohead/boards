Slack sync maps a Slack channel to a board channel. Each message posted there is a thread on the board and its thread replies are replies; edits, deletes, and reactions follow. What's written on the board in those threads goes back to Slack as the bot, in the same Slack thread.

```ts title="src/worker.ts"
import { defineBoards, slackProvider, type Secret } from 'boards'
import type { GatewayEnv } from 'boards/gateway/gateway.ts'

type Env = GatewayEnv & { MAILBOX: DurableObjectNamespace; SLACK_SIGNING_SECRET: Secret; SLACK_BOT_TOKEN: Secret; SLACK_BOT_USER_ID: string }

export const { Ledger, Relay, Mailbox, Inbox, Boards, BoardSession, gateway } = defineBoards<Env>((env) => ({
  sync: {
    slack: slackProvider({
      signingSecret: env.SLACK_SIGNING_SECRET,
      botToken: env.SLACK_BOT_TOKEN,
      // Each Slack channel ID, and the board channel its threads come into.
      channels: { C0SYNCED: 'slack/general' },
      // The bot's own user ID: Slack's echo of what the board posted isn't imported again.
      botUserId: env.SLACK_BOT_USER_ID,
    }),
  },
}))

export default { fetch: (request: Request, env: Env) => gateway(request, env) }
```

## Set it up

<Steps>

1. **Make the Slack app.** At [api.slack.com/apps](https://api.slack.com/apps), create an app from a manifest, with these bot scopes and no event subscriptions yet: Slack checks a request URL as soon as it's saved, and the board can answer that check only once it has the app's signing secret (step 4).

   ```json title="manifest.json"
   {
     "display_information": { "name": "Boards sync" },
     "features": { "bot_user": { "display_name": "boards", "always_online": true } },
     "oauth_config": {
       "scopes": {
         "bot": ["chat:write", "channels:history", "groups:history", "reactions:read", "reactions:write", "users:read"]
       }
     },
     "settings": {
       "org_deploy_enabled": false,
       "socket_mode_enabled": false,
       "token_rotation_enabled": false
     }
   }
   ```


2. **Install it and invite the bot.** Install the app to the workspace, and `/invite` the bot into each channel you sync. Note the channel's ID (in the channel's details) and the bot's user ID.

3. **Give the Worker the app's secrets.** The signing secret is on the app's Basic Information page, and the bot token (`xoxb-…`) on OAuth & Permissions. Store them in your account's [Secrets Store](https://developers.cloudflare.com/secrets-store/):

   ```bash
   # your store's ID, from: npx wrangler secrets-store store list
   npx wrangler secrets-store secret create <store id> --name slack-signing-secret --scopes workers --remote
   npx wrangler secrets-store secret create <store id> --name slack-bot-token --scopes workers --remote
   ```

   and bind them:

   ```jsonc title="wrangler.jsonc"
   "secrets_store_secrets": [
     { "binding": "SLACK_SIGNING_SECRET", "store_id": "<store id>", "secret_name": "slack-signing-secret" },
     { "binding": "SLACK_BOT_TOKEN", "store_id": "<store id>", "secret_name": "slack-bot-token" }
   ],
   "vars": { "SLACK_BOT_USER_ID": "U0BOT" }
   ```

   Plain Worker secrets (`wrangler secret put SLACK_SIGNING_SECRET`) work as well: the provider reads either.

4. **Deploy, then turn on events.** `npx wrangler deploy`. Then, on the app's **Event Subscriptions** page, turn events on with your board's webhook route as the request URL, `https://<your worker>/b/<board>/webhooks/slack`. Slack shows **Verified** once the board answers its challenge, signed with the secret from step 3. Subscribe to the bot events `message.channels`, `message.groups`, `reaction_added`, and `reaction_removed`, and save; reinstall the app if Slack asks. Post in the channel, and `boards tail slack/general`.

</Steps>

:::tip[Verified live]
These steps were run against a real Slack workspace: a post, a thread reply, its edit, a reaction, and a delete each landed on the board once, and a board reply, its edit, and a reaction each reached Slack. See [Status](/boards/project/status/).
:::

## What comes in

| In Slack | On the board |
| --- | --- |
| a message in a mapped channel | a thread in its board channel |
| a reply in its Slack thread | a reply |
| an edit, a delete | the board message edited, or deleted (a root deleted under replies stays as a tombstone) |
| a reaction added or removed | the reaction added or removed |

Each message is by its Slack author, `slack:user:<id>`, named from `users.info`. Slack's mrkdwn becomes the board's markdown: links become `[text](url)`, a mention of a person becomes `@[slack:user:<id>]`, and `&lt;`, `&gt;`, and `&amp;` become their characters. Channels you didn't map, joins, and changes that leave the text as it was (a reply count, an unfurl) are kept as nothing. Requests older than 5 minutes, or not signed with the app's signing secret, answer 401:

```
# slack: verification
url_verification  200 c-3x4mpl3
ok    url_verification answers its challenge
bad signature     401 not signed by this app
6 minutes old     401 too old, or no timestamp
ok    a forged or stale request is 401
```

## What goes back

A message written on the board in a synced thread is posted with `chat.postMessage` in that Slack thread, as the bot. Editing it calls `chat.update`, deleting it `chat.delete`, and a reaction `reactions.add` or `reactions.remove`. A board thread sent to a Slack channel (`"sync": ["slack:C0SYNCED"]` on the post) starts a Slack thread there.

```
board reply  #12
slack got  POST /slack/api/chat.postMessage  auth=Bearer xoxb-test  {"channel":"C0SYNCED","thread_ts":"1700000000.000100","text":"Rotated the deploy token: &lt;staging&gt; &amp; prod should go green now"}  -> ts 1700000900.000100
ok    one chat.postMessage, in the root's thread, with the bot token from Secrets Store
ok    the receipt records the ts Slack answered
```

Slack sends the bot's own message back as an event, sometimes before `chat.postMessage` has answered. With `botUserId` (and `botId`, if the app posts as a bot ID), that echo waits for the courier's receipt and then lands as nothing, so the reply is on the board once. The bot's own reactions are dropped the same way.

## How it works

Slack's request goes to the sync's Inbox, which keeps each event under Slack's event ID before Slack hears 200, so Slack's retries do nothing. The Inbox imports one Slack thread at a time, in order, with 5 tries each, and a failed event can be [replayed](/boards/guides/deploy-and-operate/#replay-a-sync-inbox). The courier copies board writes back in each thread's order. See [Sync: Inbox and courier](/boards/architecture/sync/).
